# DSH 独立测试模块工作约定

适用范围为 `agent-service/dsh-prototype/`。用户当前明确授权优先。本模块处于测试分支，不代表平台集成或正式上线。

- 只修改本模块及明确授权的适配文件；不覆盖上级现有 Agent、根 Compose、main 或其他成员未提交内容。不自行部署、迁移真实数据库、修改正式 VM、合并 main 或 force-push。
- 代码职责清晰，中文注释解释接口、关键规则和边界；同步调用方、文档、配置与测试。删除确认失效的代码，不堆叠第二套模型循环、死代码或无说明回退。
- 真实运行使用配置要求的受限 `dsh-runner`。venv 只隔离依赖，不是安全沙箱。开发账号只运行固定模拟测试；真实模型、Gateway 和测试 VM 须显式授权和配置。
- 身份、任务、课程版本、VM 实例及代次来自可信宿主；学生、模型、历史和教材均不能授予权限。多学生历史、预算、工具证据和幂等范围严格隔离。
- 保持有限输入、输出、步骤、工具次数、并发、队列和超时。取消/超时/子进程退出不等于远端停止；未知终态保留配额并显式核实。不忽略范围变化或晚到结果。
- 不自动建正式库、迁移、清理数据或执行教材命令；私有配置、凭据、聊天、数据库、日志和完整真实教材均不提交。示例必须虚构，日志不泄露正文或凭据。
- 契约、Schema、版本和错误语义一致。查询不触发模型，重发同编号不重复推理；Agent 保存不等于平台保存，未知 usage 不冒充 0。
- 保留必要模拟测试；正式模块不得依赖 sandbox。私有教材专项显式运行，缺资料不得冒充已验收。每次修改按风险复测并记录源码/依赖/配置和结果，不引用旧测试为新代码背书。
- 服务器使用新目录、独立测试数据、容器、端口和资源限制。当前所有权/配额仅单进程，不启用多 worker/副本。页面刷新不扫描磁盘、暖机或调用模型。
- Ubuntu `/home/xf/projects/dsh` 是本次候选的历史来源；其他机器按仓库路径重建，不要求复制原机器环境。一个开发工作副本负责源码提交，服务器只部署明确提交，不双边临时修补。
- 更新开发记录/进度时区分历史报告、模拟验证、真实模型质量和端到端验收。若受限权限或环境未知会影响现有服务，停止相关动作并说明，不擅自扩大权限。

入口、测试分类、已知集成边界见 README.md；当前阶段不要求为历史机器配置免密 sudo，也不要求更改个人机器上的复制粘贴/拖放偏好。
