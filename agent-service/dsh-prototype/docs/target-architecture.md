## 开发规则

- 独立与共享：身份、任务、记忆、权限和请求状态独立；共享Agent及模型服务，不给每位学生常驻一份模型。
- 双重限制：已实现总准入（默认5）与独立准备（2）/DSH执行（1）控制，准备和重核有预算。不能因提前读取放大数据库压力。
- 公平与取消：保留每学生占用限制、有限队列、等待超时和重复请求去重；取消和资源释放不能凭猜测。
- 动态调低并发：已实现可信宿主CAS配置更新；限制后续放行，已运行请求正常结束。管理HTTP当前只读。
- 最终一致性：准备后、排队后及最终保存时按需再核对可信范围与版本；旧资料不能覆盖更正、删除或新环境。
- 可靠交付：聊天和交付记录均保存后才返回；平台最终保存待接。断线重用原请求编号，重启先暂停/核实/对账，不自动重跑。
- 记忆读取：已默认一次近期4条候选，可信宿主明确选择早期历史页时最多16条；仍受模型4轮/2400字符预算、任务范围和删除下界限制。无自动语义检索。
- 资源预算：输入、输出、运行时间、工具和数据库均有边界；在线人数不等于同时推理数。
- 模型并发：继续使用当前已验证的限制做实际模型测试；更高并发先用替身验证程序规则，再用硬件压测决定。
- 跨进程：单进程门控不能当全局限流；多进程或多服务器前必须统一模型总预算和请求归属。
- 真实进度：排队、资料读取、DSH、工具、校验和保存产生可关联事件；真实/模拟/未知与更新时间明确显示。
- 不提前交付事实：进度提示可先显示，工具事实须校验；保留平台最终保存完成的语义。
- 后台整理：只有将来确需复杂摘要时再加低优先级、有预算的后台任务，写回核对来源与版本；目前不增加额外整理Agent。
- DSH扩展：优先配置、适配器和公开事件，避免长期修改核心；官方主线能力须对照本机0.2.1rc2验证。
- 渐进升级：先单进程验证；不预先强制安装Ray、Redis、LiteLLM或vLLM。服务器明确后再选择。
