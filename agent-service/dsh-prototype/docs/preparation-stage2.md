# 第二阶段：有界资料准备与记忆读取

状态：本地开发、模拟验收及3例真实Qwen核心行为复核完成。真实服务器容量仍待测试。

## 现在怎么工作

```text
学生问题与可信范围
        │
        ▼
总准入与每学生配额（默认共5个请求）
        │
        ▼
等待资料准备 → 最多同时准备2个
        │
        ▼
接受问题，读取教材快照、有效目标与少量前文
        │
        ▼
核对范围、任务、pending记录与记忆版本
        │
        ▼
释放准备名额，等待DSH名额
        │
        ▼
再次核对范围与记忆（默认最多2秒）
        │
        ▼
DSH／模型与受控工具（Mac仍并发1）
        │
        ▼
校验，最终事务再核对版本
        │
        ▼
保存确认 → 返回学生 → 释放名额
```

A读历史慢、B资料已准备好时，B可以先调用模型；A继续占用自己的准备名额。总请求上限保留，不能无限提前查数据库。DSH名额仍覆盖模型、工具、结果校验与保存，不在工具等待时提前释放；远端取消未验收。

## 读多少记忆

- 当前任务有效目标、尝试、未解决问题和同学习记录偏好沿用原权限、版本和摘录预算；不额外调用模型生成摘要。
- 默认一次查询近期最多4条候选记录，不是保证4轮成功问答。失败、旧工具回答、超长或已失效记录会省略并标记上下文不完整，不为了凑满4轮自动翻页。
- 可信宿主明确选择history_mode='earlier'才查询较早记录，一次最多16条候选。无锚点时跳过最近窗口；传history_before时按指定序号向前读。学生、任务、课程修订和记忆删除下界始终有效。
- 模型前文仍最多4轮/2400字符；查询16条不代表发送16轮。字符预算不是token预算。
- 尚无自然语言语义检索或自动推断历史位置。未来平台可以传学生选择的历史位置；查不到时应补充信息，不能假装看过全部历史。

```python
reply = service.answer(request, store=task_store, handle=verified_handle)
older = service.answer(other_request, store=task_store, handle=verified_handle,
                       history_mode='earlier', history_before=known_sequence)
```

教材由可信调用方传入有限快照；本轮准备负责其验证/组装与记忆读取。平台教材接口的真实I/O未来须放在同样的总准入/准备边界内，本轮没有接平台课程数据库。

## 数量、时间与取消

| 项目 | 初始值与语义 |
|---|---|
| 总准入 | max_active + max_waiting，默认5，覆盖准备、等准备、等DSH和执行 |
| 每学生 | 默认1个未结束请求，贯穿准备至保存 |
| 准备 | 同时最多2个；等准备最多5秒，准备预算3秒 |
| 执行前重核 | 新建2秒预算，不把DSH排队误算成准备超时 |
| DSH | Mac仍并发1；等待DSH默认10秒，原有180秒总时限/120秒SDK时限继续生效 |
| SQLite | 同线程截止时间；锁等待不超过剩余预算，长查询用progress handler中断，回滚/关闭后清理pending |
| 不响应预算的适配器 | 继续占准备与总准入直到返回，随后拒绝旧结果；不能丢弃仍在运行的线程再堆新任务 |
| 等待取消/超时 | 未调用模型；已接受pending尽力结束，清理失败标recovery_required，不自动重试 |

动态降低上限保留在途与已接受者，只限制新放行，可能暂超新上限。已等待者保留原截止时间。max_waiting是额外总准入名额，不是另开无限准备队列。新的准备限制也能由可信宿主CAS调整；页面当前仍只读。

学生显式提交的目标/偏好可在准备阶段已经可靠记住，随后取消模型等待不撤销这条声明；更正与撤销走原有接口。

## 接口、排错与升级

answer_chat保留同步入口，与资源宿主共用ChatSession.prepare/execute，未复制Agent循环。快照只存在于单次请求；Session不可重复执行，客户端/模型不能提交“已准备对象”绕过检查。

ChatStore新增只读check_pending(handle, request_id, sequence, question)。新数据库适配器必须核对当前范围、原请求与pending状态；不能用重新accept创造执行权。TaskMemoryStore还核对任务归属和归档。最终保存保留事务版本检查。

管理面板新增总占用、准备/等准备、DSH/等DSH和分段耗时。每轮最多16段脱敏计时，结束只写一次，不增加后台摘要模型。

| 原因码 | 含义 |
|---|---|
| preparation_queue_timeout | 等待准备名额超时，尚未接受聊天pending |
| preparation_timeout | 准备或执行前复核超过预算，未调用模型 |
| queue_timeout / cancelled | 等DSH超时/取消，已接受pending尽力结束 |
| memory_changed | 记忆更正/删除，旧快照拒绝调用模型或交付 |
| stale_scope / stale_request | 课程、环境修订、原请求或删除状态已变化 |
