# 任务记忆与管理接口

本轮在Ubuntu独立原型开发，不改AIVirTeach，不连接正式数据库或真实环境。测试和管理页面只使用sandbox虚构数据。管理本身不调用模型，问答沿用既有DSH流程与资源门控。

## 入口与依赖

- `dsh_tutor/task_memory.py`：本地SQLite任务存取适配。应用提供可信学生/学习记录/课程版本/课时/实例/代次；任务ID只是定位符，不能作为认证凭据。
- `dsh_tutor/task_memory_api.py`：与HTTP解耦的管理应用接口。`execute(trusted_handle,payload)`不接受客户端自报student_id或handle。
- `sandbox/task_memory_demo.py`与同名HTML：固定虚构身份、仅回环监听的演示，不是生产登录系统。只读开发看板与此写入演示分开。
- `storage.py`原子接受/结束抽成共享事务内核，任务适配器复用它；不另写模型循环。

```python
from dsh_tutor.task_memory import TaskRepository, migrate_task_memory

# 由可信应用在停止旧请求后显式迁移v2到v3；不要每次问答迁移。
migrate_task_memory(sqlite_store)
repo = TaskRepository(sqlite_store)
# 有正式练习ID就显式create并重用；没有时默认课时任务稳定，不随VM重建。
task = repo.ensure_lesson_task(trusted_handle)
bound = repo.bind(trusted_handle, task['task_id'])
# service是启动时创建并共用的ResourceManagedTutor。
# answer_chat检测任务适配器后自动启用同一个存储的记忆版本保护。
reply = service.answer(question, store=bound, handle=trusted_handle)
```

任务属于学生的同一学习记录、课程版本和课时，和VM实例分开。多页面分别传任务绑定，不设置学生全局current_task。回复`ChatReply.task_id`供应用核对归属。当前存储仍每学习记录只允许一个活动环境修订和一个pending请求，不声称支持同一学习记录内多个环境同时活动；不同页面同一环境下的不同任务可独立选择。

## 记忆规则

- 目标按任务保存，换VM仍可保留；尝试/未解决问题在旧环境修订下标为`stale_environment`，不作为当前有效记忆加载。
- 偏好仅在同学生同学习记录内跨任务/实例共享，不跨学习记录或自动跨课程。
- 默认只读取当前任务及共享偏好，最多4项；单项300字符、记忆输入默认1200字符；保留既有4轮/2400字符历史及总预算。这些是字符上限，不冒充token计量。
- 修改已有目标时，将旧的有效尝试/未解决问题标为`needs_review`，并增加其版本；不删除、不默认为新目标已尝试。学生可编辑同一内容重新确认其自述。目标未变则不无效化。
- 同一条明确声明同时包含新目标和新尝试时，先更新目标，再登记新尝试，不依赖行顺序。
- 原文摘录保留来源请求、字符范围、时间和版本。来源是学生自述，不是当前工具观察、成绩或授权。
- 新问答仍仅识别四个明确前缀；管理页面通过显式编辑登记。普通自然语言不会自动建立任务或覆盖长期记忆。模糊意图可在回答中询问，但本轮没有可靠自然语言意图分类器。
- 本轮未实现跨任务按需检索；明确提及旧任务应先由界面切回或通过后续受控检索接口处理，不能假装已能任意回忆。

## 更新、撤销与并发

管理命令为`list_tasks`（游标分页）、`ensure_task`、`create_task`、`view`、`edit`、`revoke`、`unassigned`。edit必须携带expected_revision与新的request_id，revoke必须比较版本。旧页面不能覆盖新修改；冲突返回稳定原因码，刷新后核对，不自动重试修改。

编辑来源保存为`memory_edit`管理事件，复用原始记录容量限制；不伪造模型回答。撤销清空当前记忆正文并保留版本，但原聊天、原编辑事件和备份未彻底擦除。来源历史删除会在同一事务撤销引用它的任务记忆/共享偏好。

每个任务有对话下界和单调版本；共享偏好的版本影响本学习记录所有任务。更正或撤销后，旧助手回声不再送入模型。最终答案写入与版本检查在同一事务；推理期间发生相关修改就拒绝交付旧答案。另一个任务的无关目标修改不使当前请求无故失败。

同一请求编号不能从任务A转绑到B，重复问答只重放原保存结果，不重复调用模型。选择另一个标签页的任务不改变在途请求的归属；学生端聊天渲染仍须按返回task_id更新相应页面，这部分生产界面尚未接入。

## 显式迁移与未知数据

旧库v1先按既有显式步骤升到v2；`migrate_task_memory`仅将v2事务升级为v3，发现pending拒绝迁移，需可信应用先确认旧请求是否已结束并处理。函数可重复调用，不自动复制活动数据库。

旧消息与旧记忆保持原样，标为未归类；不会注入新任务。`unassigned`有界查看当前范围旧记忆和数量，不提供自动认领。v3的未绑定普通问答入口拒绝接受请求，防漏传任务后混读历史；旧v1/v2调用及历史查看继续兼容。尚未建立旧数据认领向导、正式归档/备份策略或物理擦除。

## 页面与启动

在Ubuntu项目内运行：

```text
.venv/bin/python sandbox/task_memory_demo.py --port 8790
```

浏览器访问Ubuntu本机`http://127.0.0.1:8790/`。Windows需要沿用SSH做同端口回环转发；本轮已临时建立。Ctrl+C结束演示/转发，虚构SQLite记录仍保留。虚构库固定为`sandbox/results/task-memory-demo/fictional.db`，不接受任意库路径，不启动DSH，因此此页面无需以dsh-runner调用模型；真实DSH运行仍沿用受限身份约定。

页面每标签页使用sessionStorage保留选择，仅保存任务定位符/标题，不作认证或模型记忆。刷新能保持当前选择，页面间不共享可变当前任务；关闭标签页后不保证下次自动恢复选择。数据库中的任务/记忆不因此消失。无后台模型整理、轮询、向量索引或额外依赖。

回环HTTP入口校验Host、Origin与页面令牌，限制请求大小，写入JSON通过textContent展示，不执行学生HTML。此令牌只是本机演示请求保护，不能替代生产认证。本轮未扩大网络监听或runner权限。

## 验证边界

自动回归覆盖旧功能、迁移拒绝/回滚、学生/课时/任务隔离、VM变化、来源、目标变更、管理版本冲突、并发更正、旧回复拒绝、来源删除、重启和实际HTTP管理链路。问答测试替换模型传输，管理操作零模型调用。

浏览器人工自动操作已核对新增/切换任务、修改目标、待确认提示、偏好共享、撤销及刷新保留。实际模型语义、多人吞吐、正式平台、跨任务语义检索、持久工具证据、归档和自动扩缩容仍未验收或未实现。最终测试数量和代码指纹以`development/task-memory-20261030.json`为准。

本轮三例实际模型核心复核已通过，仍有回答偏长/额外追问的质量项。复核入口可复用：

```text
sudo -u dsh-runner /home/xf/projects/dsh/.venv/bin/python /home/xf/projects/dsh/sandbox/task_memory_acceptance.py
```

它在受限账号现有runner-check可写位置新建独立虚构夹具，串行验证任务A目标、任务B无目标隔离、返回A更正目标，共最多3次DSH问答。各例使用新进程；每轮原始报告独立保留，机械检查后仍需人工复核回答措辞。源码冻结后再运行，sudo密码仅在Ubuntu本机输入。

本轮报告交付已修复：latest报告指针由xf持有，并仅给dsh-runner该文件写权限；原始独立夹具报告仍保持受限。下次同一验收命令结束后可直接读取latest，无需再次sudo导出。模型3例耗时17.72/5.28/5.23秒，仅小样本，不是并发容量结论。
